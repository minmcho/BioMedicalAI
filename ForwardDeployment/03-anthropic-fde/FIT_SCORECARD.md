# Anthropic FDE — Good-Fit Scorecard (self-score honestly, monthly)
A "good fit" is not knowledge. It is evidence a screener can verify in 10 minutes.
Score each 0-2: 0 = no evidence, 1 = partial/indirect, 2 = direct public evidence.

| # | Dimension (what they screen) | Min Oct 2026 | Target evidence (what "2" looks like) |
|---|---|---|---|
| 1 | Builds production LLM apps with Claude | 0 | Live Claude API app + public repo + README with architecture |
| 2 | MCP servers, sub-agents, agent skills | 1 | Public MCP server + a multi-agent system with tool schemas, shipped |
| 3 | Evaluation rigor | 1 | Graded eval set, baseline-vs-candidate regressions, transcript/failure analysis published |
| 4 | Deployment inside customer constraints | 0 | Pilot case study: real users, governance/security handled, adoption result |
| 5 | Customer-facing delivery | 1 | Discovery docs, scope, playbook; a reference/recommendation from a user group |
| 6 | Communication across levels | 1 | One public write-up + a 20-min case walkthrough rehearsed (exec and engineer versions) |
| 7 | Domain wedge (health / life sciences) | 2 | Already direct: regulated lab, LIMS, genomics ML — keep it front and center |
| 8 | Responsible AI / values | 1 | Written safety design for a real system (no-diagnosis guardrails, data handling, human oversight) |
| 9 | Agency under ambiguity | 1 | Log of 48-hour POC sprints shipped from vague briefs |
| 10 | Coding fluency (Python, live) | 1 | Timed practice log; production Python visible in public repos |

Oct 2026 total: 9/20 — a Stretch. Good-fit threshold for a serious application: 15+/20, with no zero in rows 1, 3, or 4.
Fastest points: row 1 (+2, Phase B build), row 3 (+1, publish evals), row 2 (+1, public MCP server), row 8 (+1, write the safety doc). That alone reaches ~14-15 by Week 7.
